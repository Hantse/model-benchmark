# Règles du tester

Lire PROMPT.md et FEATURES.md. Implémenter les fonctionnalités dans les chemins
editablePaths du benchmark.json. Les stubs sont intentionnels ; le projet doit
compiler avant et après. Ne modifier ni tests, manifeste, instructions, dépendances
des tests, hooks publics ni commandes de validation. Ne désactiver, ignorer ou
remplacer aucun test. Aucun réseau externe dans le produit final, secret réel,
service de production, base externe ou location cloud. Garder les dépendances
épinglées. Les tests ne représentent pas une preuve de sécurité de production.
À la fin, donner les fichiers changés et les commandes réellement exécutées.
